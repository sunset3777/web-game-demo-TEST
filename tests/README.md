# 測試說明

## 如何執行

```
npm test
```

用 Node 內建的 `node:test` 跑 `tests/*.test.js`，不需額外安裝套件。輔助工具放在 `tests/helpers/`。

## 三組測試

- `save-contract.test.js`：存檔與傳承的契約。
- `fixed-seed-flow.test.js`：固定亂數種子玩完整一世的快照測試。
- `invariants.test.js`：多種子整世模擬中，每一步都不該違反的不變條件。

## 快照測試的意義與限制

`fixed-seed-flow.test.js` 裡的 `EXPECTED_LIVES` 記錄的是「目前規則下的結果」。

- 它能抓到：重構（改名、拆檔）不小心改變了行為。重構時快照一個字都不該變。
- 它不能證明：規則本身是對的、數值是平衡的。快照只是現況紀錄。
- 有意改規則、數值、事件資料或亂數消耗順序時，快照會變紅，這是設計上的行為。請先確認新結果合理，再用 `helpers/summarizeLife.js` 重新產生並整段取代，不要為了讓測試變綠而盲目更新。

## 已修好的已知問題

曾有 5 個測試（規則層 4 個、畫面層 1 個）故意保持失敗、提醒尚未修的問題；這些問題已依設計者的決定修好，測試現在全部通過，`npm test` 與 `npm run test:ui` 都應該是 0 個失敗：

1. 死亡後不能回到死亡前的進度（審查 4-1）：死亡時存檔寫成 `alive=false` 的結局狀態，標題不出現「繼續」，改出現「為 姓名 留下筆記」回到結局畫面。
2. 傳承檔寫入失敗時保留舊存檔、不說已留下筆記，並提示存檔失敗（審查 4-2）。
3. 較新版本的存檔與傳承檔拒絕載入、不降版、不覆蓋，標題提示「這份存檔來自較新版本」（審查 4-6）。
4. 死亡或退隱後玩家操作一律不做任何事（測試補充發現，審查未列）。

審查指 `docs/設計討論/10_Codex新人審查.md` 第 4 節。當時記錄舊行為的「現況：…」測試已改寫成新行為的正式測試或刪除。

## 之後再發現已知問題時

1. 寫一個描述「期望的正確行為」的測試，前面加「已知問題（目前會失敗…）」註解說明原因，不標待辦、不略過。
2. 修好 `src/` 的對應問題後，該測試會自動變綠；把註解改成一般說明。
3. 若旁邊有記錄舊行為的「現況：…」測試，此時會變紅，請改寫成新行為的測試或刪除。
