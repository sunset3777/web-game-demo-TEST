# 測試說明

## 如何執行

```
npm test
```

用 Node 內建的 `node:test` 跑 `tests/*.test.js`，不需額外安裝套件。輔助工具放在 `tests/helpers/`。

## 三組測試

- `save-contract.test.js`：存檔與傳承的契約。
- `fixed-seed-flow.test.js`：固定亂數種子玩完整一世的快照測試。
- `invariants.test.js`：多種子整世模擬中，每一步都不該違反的不變條件。

## 快照測試的意義與限制

`fixed-seed-flow.test.js` 裡的 `EXPECTED_LIVES` 記錄的是「目前規則下的結果」。

- 它能抓到：重構（改名、拆檔）不小心改變了行為。重構時快照一個字都不該變。
- 它不能證明：規則本身是對的、數值是平衡的。快照只是現況紀錄。
- 有意改規則、數值、事件資料或亂數消耗順序時，快照會變紅，這是設計上的行為。請先確認新結果合理，再用 `helpers/summarizeLife.js` 重新產生並整段取代，不要為了讓測試變綠而盲目更新。

## 已知問題測試（目前會失敗）

目前有 4 個測試故意讓它失敗：它們寫的是「期望的正確行為」，對應尚未修的已知問題，每個測試前面都有「已知問題」註解說明原因。我們不把它們標成待辦或略過，所以 `npm test` 會顯示 4 個失敗、退出碼為 1，這是有意的，用來提醒債務還沒還：

1. 死亡後存檔應被清掉（審查 4-1）。
2. 傳承檔寫入失敗時不該清舊存檔（審查 4-2）。
3. 較新版本的存檔不該被降回現版本號（審查 4-6）。
4. 死亡後呼叫 `doAction` 不該改變狀態（測試補充發現，審查未列）。

審查指 `docs/設計討論/10_Codex新人審查.md` 第 4 節。每個已知問題旁邊另有一個「現況：…」測試，記錄目前的實際行為（這些會通過）。

## 問題修好之後

1. 修好 `src/` 的對應問題。
2. 該「已知問題」測試會自動變綠；把它前面的「已知問題」註解刪掉或改成一般說明。
3. 對應的「現況：…」測試此時會變紅，請更新或刪除它。
